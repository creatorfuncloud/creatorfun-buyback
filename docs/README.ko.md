# CREATORFUN 영구 바이백 & 소각

CREATORFUN 토큰의 크리에이터가 자기 거래 수수료의 일부를 **영원히 자기 토큰을 사서 소각하는 데 쓰겠다고 약속**할 수 있게 해주는 온체인 프로그램입니다.

- 웹사이트: https://creatorfun.cloud
- 런치패드 규칙 (변경 불가 설정): https://github.com/creatorfuncloud/creatorfun-config
- 프로그램 주소: *배포 후 여기에 공개*
- 상태: **아직 배포 전, 감사 받지 않음** — [출시 계획](#출시-계획) 참고

> 영어 원문: [README.md](../README.md) (내용이 다르면 영어 원문이 기준입니다)

---

## 왜 만들었나

CREATORFUN 크리에이터는 자기 토큰의 모든 거래에서 0.80%를 받습니다. creatorfun.cloud, pump.fun, Jupiter 등 어디서 거래되든 모든 거래가 그 토큰의 Meteora 풀을 거치기 때문입니다.

이 프로그램으로 크리에이터는 홀더에게 약속할 수 있습니다: *"내 수수료의 X%는 항상 토큰을 사서 소각하는 데 쓰인다."*
약속은 깰 수 없어야 의미가 있습니다. 그래서 한 번 켜면 **끄거나 바꾸는 명령 자체가 없습니다. 크리에이터에게도, CREATORFUN에게도.** 남아 있는 단 하나의 권한(시범 기간의 프로그램 수정 권한)은 [시범 기간](#시범-기간-남아-있는-단-하나의-권한)에 그대로 공개합니다.

## 동작 방식

1. **`enable` (켜기)** — 크리에이터가 바이백 비율(5~100%)과 실행 금액(0.1~10 SOL)을 정합니다. 프로그램은 Meteora 풀을 직접 읽어 확인합니다: Meteora 본딩커브 프로그램 소유인지, CREATORFUN 설정을 쓰는지, 서명자가 현재 크리에이터인지, 민트가 맞는지, 졸업이 시작되지 않았는지. 크리에이터는 0.005 SOL 예비금을 냅니다 (임시 계정 임대료로만 쓰이고 지급되지 않음). 그다음 Meteora의 `transfer_pool_creator`로 크리에이터 자격을 프로그램 PDA로 넘기고, **풀을 다시 읽어서 넘어간 것을 확인합니다.** 이것이 크리에이터가 내리는 마지막 결정입니다.
2. **수수료 꺼내기 (누구나 호출 가능)**
   - `claim_curve_fees` — 본딩커브의 크리에이터 거래 수수료
   - `claim_curve_surplus` — 커브 완료 후 크리에이터 몫의 잉여금
   - `claim_amm_fees` — 졸업 후 DAMM v2 풀에 잠긴 크리에이터 LP 포지션의 수수료
   wSOL로 들어온 것은 같은 명령 안에서 일반 SOL로 바뀝니다.
3. **`prepare_curve` / `prepare_amm` (가격 기록)** — 풀의 현재 가격과 슬롯을 기록합니다.
4. **`execute_curve` / `execute_amm` (실행)** — `prepare` 후 2~150 슬롯(약 1초~1분) 사이에, 가격이 매수에 불리하게 약 1% 넘게 움직이지 않았을 때만 프로그램이:
   - 모인 SOL의 `buyback_bps`만큼으로 그 토큰의 풀에서 토큰을 사고,
   - 산 토큰을 전부 소각하고 (SPL `burn`, 공급량이 실제로 줄어듭니다),
   - 나머지 SOL은 `enable` 때 저장된 크리에이터 지갑으로 보내고,
   - LP 수수료가 토큰으로 들어온 경우 같은 비율만큼 소각하고 나머지는 크리에이터에게 보냅니다.

### 실행 규칙 (프로그램에 고정, 모든 토큰 동일)

| 규칙 | 값 |
|---|---|
| 실행 가능한 때 | 모인 SOL ≥ 실행 금액, **또는** 마지막 실행 후 7일이 지났고 0.01 SOL 이상 모였을 때 |
| 실행 간 최소 간격 | 10분 |
| 한 번 최대 바이백 | 1 SOL (더 많으면 여러 번 나눠 처리) |
| 24시간 최대 바이백 | 토큰당 5 SOL |
| 가격 확인 | `execute`는 `prepare` 후 2~150 슬롯 사이에만 가능, 가격이 `prepare` 때보다 약 1% 넘게 나빠지면 실패 (sqrt 가격 기준 50bps) |
| 슬리피지 | 실행자는 `min_tokens_out > 0`을 넣어야 하고, 그보다 적게 받으면 거래 전체가 취소되어 손실이 없습니다 |
| 실행할 수 있는 사람 | CREATORFUN 키퍼는 규칙이 허락할 때 언제나, **누구나**는 마지막 실행 후 8일이 지나면 |
| 작은 지급액 | 0.001 SOL 미만의 크리에이터 지급액은 기록(`creator_owed`)해 두었다가 다음 실행 때 함께 지급, 사라지지 않음 |

## 할 수 있는 것 / 할 수 없는 것

| 할 수 있음 | 할 수 없음 (그런 명령이 존재하지 않음) |
|---|---|
| 수수료의 `buyback_bps`만큼 토큰을 사서 소각 | 바이백 끄기, 멈추기, `enable` 되돌리기 |
| 나머지를 `enable` 때 저장된 크리에이터 지갑으로 송금 | 비율, 실행 금액, 크리에이터 지갑 변경 |
| 합계(꺼낸 금액, 바이백 금액, 소각량, 지급액, 미지급액)를 온체인에 기록 | 크리에이터 자격을 되돌리거나 다른 사람에게 넘기기 |
| | 크리에이터가 아닌 지갑으로 수수료 송금 |
| | CREATORFUN, 키퍼, 그 누구든 자금 인출 (관리자 명령 없음) |

금고의 규칙 필드(`pool`, `base_mint`, `creator`, `buyback_bps`, `threshold_lamports`, `created_at`)는 **오직** `enable`에서만 쓰입니다. `lib.rs`를 검색해 보면 다른 명령은 이 값들을 쓰지 않는 것을 확인할 수 있습니다.

## 키퍼가 할 수 있는 일 (정확히)

키퍼(`5KQ2oGJbnsJiQ8GXZ1w7QCro2sYZfMEPsmvmLter4irF`)는 CREATORFUN 서버가 바이백을 제때 실행하려고 쓰는 지갑입니다.

- **할 수 있음**: 8일 공개 기간이 열리기 전에 `prepare_*`와 `execute_*`를 호출하고, `min_tokens_out`을 정하는 것.
- **할 수 없음**: 돈을 받는 것, 돈이 갈 곳을 정하는 것, 가격 확인을 건너뛰는 것, 1회·하루 한도를 넘는 것, 규칙을 바꾸는 것.
- 키퍼가 멈춰도 마지막 실행 후 8일이 지나면 누구나 실행할 수 있습니다. 수수료 꺼내기는 언제나 누구나 할 수 있습니다.
- 키퍼는 새 시세 기준 1% 슬리피지로 `min_tokens_out`을 정하고, 실패하면 새 시세로 다시 시도합니다.

## 시범 기간: 남아 있는 단 하나의 권한

시범 기간에는 버그를 고칠 수 있도록 **수정 권한(upgrade authority)을 둔 채** 배포합니다. 수정 권한이 있으면 프로그램 코드를 바꿀 수 있으므로, 시범 기간 동안 위의 약속은 CREATORFUN이 그 권한을 남용하지 않는다는 것에 기대게 됩니다. 이 위험이 다른 사람의 돈에 닿지 않도록:

- `PROBATION = true`인 동안에는 **CREATORFUN 자체 테스트 지갑**(`lib.rs`의 `PROBATION_CREATORS`)만 `enable`을 할 수 있습니다. 코드를 바꿀 수 있는 동안 외부 크리에이터의 수수료는 이 프로그램에 들어오지 않습니다.
- 수정 권한 주소와 모든 수정 내역을 이 README에 공개합니다.
- 공개 버전은 `PROBATION = false`로 바꾸고, **같은 배포에서** 수정 권한을 없앱니다 (`solana program set-upgrade-authority --final`). 그 뒤로는 CREATORFUN을 포함해 누구도 코드를 바꿀 수 없습니다.

## 알려진 한계 (꼭 읽어주세요)

- **전문 감사를 받지 않았습니다.** CREATORFUN은 감사 비용을 감당할 수 없었습니다. 대신 코드를 공개하고, 규칙은 단위 테스트가 있는 작은 순수 함수로 만들고, 단계적으로 출시합니다. 검토 후 문제를 알려주세요 — [SECURITY.md](../SECURITY.md) 참고.
- **MEV는 줄였지만 없앤 것은 아닙니다.** 바이백은 시장 매수입니다. `prepare` → `execute` 가격 확인으로 같은 블록 안의 가격 끌어올리기는 실패하고, `min_tokens_out`으로 비싸게 사는 것을 막고, 한도로 한 번·하루의 손실 크기를 제한합니다. 차익거래 위험을 감수하고 여러 슬롯 동안 조작된 가격을 유지하는 사람은 여전히 실행 조건을 조금 나쁘게 만들 수 있습니다. 한 번 실행은 최대 1 SOL입니다.
- **Meteora 계정 구조.** 프로그램은 Meteora 계정의 고정 위치 값을 읽습니다 (`lib.rs` 맨 위에 목록, 메인넷 실제 계정으로 확인). Meteora가 구조를 바꾸면 잘못 읽는 대신 실패합니다. 모든 읽기에서 소유 프로그램과 계정 구분자도 확인합니다.
- **SPL 토큰만 지원.** Token-2022 민트는 지원하지 않습니다. CREATORFUN 토큰은 SPL 토큰입니다.
- **졸업 풀은 고정.** 졸업 후에는 CREATORFUN 마이그레이션 설정과 토큰 민트로 계산한 DAMM v2 풀과, 프로그램이 보유한 LP 포지션만 사용하므로 가짜 풀을 끼워 넣을 수 없습니다.

## 크리에이터 수입이 가는 곳 (전체 목록)

CREATORFUN 설정(`creatorfun-config`) 기준: 크리에이터 거래 수수료 몫은 풀 수수료 1.25%의 80% (= 거래량의 0.80%), 크리에이터 마이그레이션 수수료 0%, 졸업 LP 잠금. 따라서 `enable` 후 크리에이터의 온체인 수입은 정확히 아래 세 가지입니다.

| 출처 | 꺼내는 명령 |
|---|---|
| 본딩커브 크리에이터 거래 수수료 | `claim_curve_fees` |
| 커브 잉여금의 크리에이터 몫 | `claim_curve_surplus` |
| 잠긴 DAMM v2 LP 포지션 수수료 | `claim_amm_fees` |

세 가지 모두 같은 규칙으로 나뉩니다: `buyback_bps` → 매수 & 소각, 나머지 → 크리에이터 지갑.

## 출시 계획

1. **데브넷**: 실제 Meteora 데브넷 풀로 모든 명령을 끝까지 테스트합니다 (`--features devnet`으로 빌드).
2. **메인넷 시범 기간**: 수정 권한을 둔 채 배포, CREATORFUN 테스트 지갑만 켤 수 있음. 수정 권한 주소와 모든 수정 내역 공개.
3. **공개**: `PROBATION = false`와 수정 권한 제거를 같은 배포에서. 그 뒤로는 누구도 코드를 바꿀 수 없습니다.

## 빌드와 검증

```bash
cargo test --manifest-path programs/creatorfun-buyback/Cargo.toml   # 실행 규칙 단위 테스트
anchor build                                                        # Anchor 0.31.1, Solana 2.1.21
sha256sum target/deploy/creatorfun_buyback.so
```

모든 push는 GitHub Actions(`.github/workflows/build.yml`)가 빌드하고, 프로그램 바이너리와 SHA-256 해시를 공개합니다.
