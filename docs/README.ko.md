# CREATORFUN 영구 바이백 · 소각 · 후원

CREATORFUN 토큰의 발행자가 자기 거래 수수료의 일부를 **영원히** 자기 토큰을 사서 소각하는 데, 후원 지갑에 보내는 데,
또는 둘 다에 쓰겠다고 약속할 수 있게 해주는 온체인 프로그램입니다.

- 웹사이트: https://creatorfun.cloud
- 런치패드 규칙 (변경 불가 설정): https://github.com/creatorfuncloud/creatorfun-config
- 프로그램 주소: *배포 후 여기에 공개*
- 상태: **아직 배포 전, 감사 받지 않음** — [출시 계획](#출시-계획) 참고

> 영어 원문: [README.md](../README.md) (내용이 다르면 영어 원문이 기준입니다)

---

## 왜 만들었나

CREATORFUN 발행자는 자기 토큰의 모든 거래에서 0.80%를 받습니다. creatorfun.cloud, Jupiter 등 어디서 거래되든 모든
거래가 그 토큰의 Meteora 풀을 거치기 때문입니다.

이 프로그램으로 발행자는 깰 수 없는 약속을 할 수 있습니다.

- *"내 수수료의 X%는 항상 토큰을 사서 소각한다."*
- *"내 수수료의 Y%는 항상 이 후원 지갑으로 간다."*

한 번 켜면 **끄거나 바꾸는 명령 자체가 없습니다. 발행자에게도, CREATORFUN에게도.** 남아 있는 단 하나의 권한(시범
기간의 프로그램 수정 권한)은 [시범 기간](#시범-기간-남아-있는-단-하나의-권한)에 그대로 공개합니다.

**SOL 코인**과 **주식페어 코인**(TSLAx 같은 주식 토큰과 짝지어진 토큰) 모두 같은 방식으로 동작합니다. 모든 금액은
그 풀의 페어 자산으로 처리됩니다. SOL 코인은 SOL, 주식페어 코인은 그 주식 토큰입니다.

## 발행자의 선택

발행할 때 발행자가 아래 네 가지 중 하나를 고릅니다. 한 번 고르면 바꿀 수 없습니다.

| 바이백 비율 | 후원 비율 | 발행자 수수료가 가는 곳 |
|---|---|---|
| 0% | 0% | 프로그램을 쓰지 않음. 지금처럼 발행자에게 |
| 1~100% | 0% | 바이백 몫은 사서 소각, 나머지는 발행자 |
| 0% | 1~100% | 후원 몫은 후원 지갑, 나머지는 발행자 |
| 자유 | 자유 | 바이백 · 후원 · 발행자, 바이백과 후원 합계 100% 이하 |

**후원 지갑**은 어떤 일반 지갑 주소든 됩니다. CREATORFUN 프로필이 없어도 되므로, 급한 사고를 당한 사람도 바로 도울
수 있습니다. 프로그램 주소는 거부합니다(SOL을 받을 수 없어 이후 모든 실행이 막히기 때문). 후원한 금액은 모두
온체인(`total_donated`)에 기록되어 Solscan에서 누구나 확인할 수 있습니다.

## 동작 방식

1. **`enable` (켜기)** — 발행자가 바이백 비율, 후원 비율, 후원 지갑, 실행 금액을 정합니다. 프로그램은 Meteora 풀과
   그 설정을 직접 읽어 확인합니다: Meteora 본딩커브 풀인지, 설정의 수수료 수령자가 **CREATORFUN 수수료 지갑**인지
   (SOL 설정과 모든 주식페어 설정이 그렇습니다), 페어 자산이 설정과 같은지, 서명자가 현재 풀 크리에이터인지, 민트가
   맞는지, 졸업이 시작되지 않았는지. 발행자는 0.005 SOL 예비금을 냅니다(임시 계정 임대료로만 쓰이고 지급되지 않음).
   주식페어 코인은 프로그램 · 발행자 · 후원 지갑의 주식 토큰 계정을 여기서 발행자 비용으로 만듭니다. 그다음
   Meteora의 `transfer_pool_creator`로 크리에이터 자격을 프로그램 PDA로 넘기고, **풀을 다시 읽어서 넘어간 것을
   확인합니다.** 이것이 발행자가 내리는 마지막 결정입니다.
2. **수수료 꺼내기 (누구나 호출 가능)**
   - `claim_curve_fees` — 본딩커브의 크리에이터 거래 수수료
   - `claim_curve_surplus` — 커브 완료 후 크리에이터 몫의 잉여금
   - `claim_amm_fees` — 졸업 후 DAMM v2 풀에 잠긴 크리에이터 LP 포지션의 수수료
3. **`prepare_curve` / `prepare_amm` (가격 기록, 바이백 1% 이상)** — 실행 조건이 채워졌을 때만 풀의 현재 가격,
   슬롯, 호출자를 기록합니다. 아직 유효한 기록은 키퍼만 덮어쓸 수 있어서, 다른 사람이 키퍼의 실행을 계속 취소시킬
   수 없습니다.
4. **`execute_curve` / `execute_amm` (실행)** — `prepare`를 호출한 같은 지갑이 25~300 슬롯(약 10초~2분) 뒤에,
   가격이 매수에 불리하게 약 1% 넘게 움직이지 않았을 때만: 바이백 몫으로 토큰을 사서 산 토큰을 전부 소각하고
   (SPL `burn`, 공급량이 실제로 줄어듭니다), 후원 몫은 후원 지갑으로, 나머지는 발행자 지갑으로 보냅니다. LP
   수수료가 토큰으로 들어온 경우 같은 비율로 소각 · 후원 · 지급합니다.
5. **`distribute` (분배, 바이백 0%)** — 실행 규칙은 같고 매수와 가격 확인이 없습니다. 후원 몫은 후원 지갑으로,
   나머지는 발행자 지갑으로 보냅니다.

### 단위

한도는 **단위**로 정해져 있습니다. 1단위는 그 풀 설정의 졸업 금액의 1/85이며, `enable` 때 온체인에서 읽습니다.

- SOL 코인은 85 SOL에 졸업하므로 **1단위 = 1 SOL**입니다.
- 주식페어 설정은 설정을 만들 때의 시세로 85 SOL 가치의 주식 토큰에 졸업하므로, 1단위는 그때 약 1 SOL 가치였던
  주식 토큰 수량입니다.

단위는 누구도 정하지 않습니다. 바뀔 수 없는 그 풀의 설정에서 나옵니다.

### 실행 규칙 (프로그램에 고정, 모든 토큰 동일)

| 규칙 | 값 |
|---|---|
| 실행 가능한 때 | 모인 금액 ≥ 실행 금액, **또는** 마지막 실행 후 7일이 지났고 0.01단위 이상 모였을 때 |
| 실행 금액 (`enable` 때 선택) | 0.1 ~ 10단위 |
| 실행 간 최소 간격 | 10분 |
| 한 번 최대 바이백 | 1단위 (더 많으면 여러 번 나눠 처리) |
| 24시간 최대 바이백 | 토큰당 5단위, 고정 24시간 구간 기준 (구간은 이전 구간이 끝난 뒤 첫 실행 때 시작하므로, 경계 앞뒤로 두 구간 한도가 가깝게 쓰일 수 있음). 남은 한도가 0.01단위 미만이면 다음 구간까지 기다림 |
| 가격 확인 | `execute`는 `prepare`한 같은 지갑이 25~300 슬롯 사이에만 가능, 가격이 `prepare` 때보다 약 1% 넘게 나빠지면 실패 (sqrt 가격 기준 50bps) |
| 슬리피지 | 프로그램이 온체인에서 최소 수량을 계산합니다: 기록된 가격으로 수수료 · 가격 영향 없이 받을 수량의 75% 이상. 실행자는 이보다 높게(`min_tokens_out`)만 요구할 수 있고 낮출 수 없습니다. 그보다 적게 받으면 거래 전체가 취소되어 손실이 없습니다 |
| 실행할 수 있는 사람 | CREATORFUN 키퍼는 규칙이 허락할 때 언제나, **누구나**는 마지막 실행 후 8일이 지나면 |
| 작은 지급액 | 0.001단위 미만의 지급액은 기록(`creator_owed`, `donee_owed`)해 두었다가 다음 실행 때 함께 지급, 사라지지 않음 |

## 할 수 있는 것 / 할 수 없는 것

| 할 수 있음 | 할 수 없음 (그런 명령이 존재하지 않음) |
|---|---|
| 바이백 몫으로 토큰을 사서 소각 | 끄기, 멈추기, `enable` 되돌리기 |
| 후원 몫을 `enable` 때 저장된 후원 지갑으로 송금 | 두 비율, 실행 금액, 발행자 지갑, 후원 지갑 변경 |
| 나머지를 `enable` 때 저장된 발행자 지갑으로 송금 | 크리에이터 자격을 되돌리거나 다른 사람에게 넘기기 |
| 합계(꺼낸 금액, 바이백 금액, 소각량, 후원액, 지급액, 미지급액)를 온체인에 기록 | 후원 지갑과 발행자 지갑이 아닌 곳으로 수수료 송금 |
| | CREATORFUN, 키퍼, 그 누구든 자금 인출 (관리자 명령 없음) |

금고의 규칙 필드(`pool`, `config`, `base_mint`, `quote_mint`, `creator`, `donee`, `buyback_bps`, `donation_bps`,
`threshold`, `unit`, `created_at`)는 **오직** `enable`에서만 쓰입니다. `lib.rs`를 검색해 보면 다른 명령은 이
값들을 쓰지 않는 것을 확인할 수 있습니다.

## 키퍼가 할 수 있는 일 (정확히)

키퍼(`5nMsHjBcHCtH2wu1M5BSymsZLwt3oosdk82bwXvXpd4t`)는 CREATORFUN 서버가 금고를 제때 실행하려고 쓰는 지갑입니다.
수수료 지갑이나 테스트 지갑과 다른 별도 키입니다. (데브넷 테스트 빌드는 `5KQ2oGJbnsJiQ8GXZ1w7QCro2sYZfMEPsmvmLter4irF` 사용)

- **할 수 있음**: 8일 공개 기간이 열리기 전에 `prepare_*`, `execute_*`, `distribute`를 호출하고, 유효한 기록을
  새로 덮어쓰고, 온체인 최소 수량보다 높은 `min_tokens_out`을 요구하는 것.
- **할 수 없음**: 돈을 받는 것, 돈이 갈 곳을 정하는 것, 가격 확인을 건너뛰는 것, 온체인 최소 수량보다 낮추는 것,
  1회 · 하루 한도를 넘는 것, 규칙을 바꾸는 것.
- 키퍼가 멈춰도 마지막 실행 후 8일이 지나면 누구나 실행할 수 있습니다. 수수료 꺼내기는 언제나 누구나 할 수 있습니다.
- 키퍼는 새 시세 기준 1% 슬리피지로 `min_tokens_out`을 요구하고(온체인 최소 수량보다 높게), 실패하면 새로 prepare
  해서 다시 시도합니다.

## 시범 기간: 남아 있는 단 하나의 권한

시범 기간에는 버그를 고칠 수 있도록 **수정 권한(upgrade authority)을 둔 채** 배포합니다. 수정 권한이 있으면 프로그램
코드를 바꿀 수 있으므로, 시범 기간 동안 위의 약속은 CREATORFUN이 그 권한을 남용하지 않는다는 것에 기대게 됩니다.
이 위험이 다른 사람의 돈에 닿지 않도록:

- `PROBATION = true`인 동안에는 **CREATORFUN 자체 지갑**(`lib.rs`의 `PROBATION_CREATORS`)만 `enable`을 할 수
  있습니다. 코드를 바꿀 수 있는 동안 외부 발행자의 수수료는 이 프로그램에 들어오지 않습니다.
- 수정 권한 주소와 모든 수정 내역을 이 README에 공개합니다.
- 공개 버전은 `PROBATION = false`로 바꾸고, **같은 배포에서** 수정 권한을 없앱니다
  (`solana program set-upgrade-authority --final`). 그 뒤로는 CREATORFUN을 포함해 누구도 코드를 바꿀 수 없습니다.

## 알려진 한계 (꼭 읽어주세요)

- **전문 감사를 받지 않았습니다.** CREATORFUN은 감사 비용을 감당할 수 없었습니다. 대신 코드를 공개하고, 규칙은 단위
  테스트가 있는 작은 순수 함수로 만들고, 단계적으로 출시합니다. 검토 후 문제를 알려주세요 — [SECURITY.md](../SECURITY.md) 참고.
- **MEV는 줄였지만 없앤 것은 아닙니다.** 바이백은 시장 매수입니다. `prepare` → `execute` 가격 확인으로 같은 블록
  안의 가격 끌어올리기는 실패하고, 25슬롯 대기 때문에 끌어올린 가격이 약 10초 동안 차익거래를 버텨야 하고, prepare한
  지갑만 실행할 수 있고, 온체인 최소 수량으로 아주 나쁜 체결을 막고, 한도로 한 번 · 하루의 손실 크기를 제한합니다.
  차익거래 위험을 감수하고 그동안 조작된 가격을 유지하는 사람은 여전히 실행 조건을 나쁘게 만들 수 있습니다. 한 번
  실행은 최대 1단위입니다.
- **주식 토큰에는 발행사가 있습니다.** 토큰화 주식(예: TSLAx 같은 xStocks)은 Token-2022 토큰이고, 발행사는 이
  프로그램이 없앨 수 없는 권한을 가집니다: 전송 정지, 어떤 계정의 토큰이든 옮기기(영구 위임), 계정 동결, 나중에
  전송 훅 추가. 발행사가 정지하거나 동결하면 주식페어 코인의 실행은 풀릴 때까지 멈추고, 전송 훅을 추가하면 프로그램이
  그것을 지원하도록 수정될 때까지 실패합니다. SOL 코인은 영향이 없습니다.
- **`enable` 전 수수료.** `enable` 전에 꺼내지 않은 발행자 수수료는 그 뒤 프로그램 소유가 되어 다른 수입과 똑같이
  나뉩니다.
- **실행자가 내는 임대료.** 지급에 새 토큰 계정이 필요하면(예: LP 수수료가 토큰으로 들어와 발행자의 토큰 계정이 필요할
  때) 그 실행을 호출한 사람이 임대료를 냅니다.
- **Meteora 계정 구조.** 프로그램은 Meteora 계정의 고정 위치 값을 읽습니다(`lib.rs` 맨 위에 목록, 메인넷 실제 계정으로
  확인). Meteora가 구조를 바꾸면 잘못 읽는 대신 실패합니다. 모든 읽기에서 소유 프로그램과 계정 구분자도 확인합니다.
- **졸업 풀은 고정.** 졸업 후에는 CREATORFUN 마이그레이션 설정과 두 민트로 계산한 DAMM v2 풀과, 프로그램이 보유한
  LP 포지션만 사용하므로 가짜 풀을 끼워 넣을 수 없습니다.

## 발행자 수입이 가는 곳 (전체 목록)

CREATORFUN 설정(`creatorfun-config`) 기준: 발행자 거래 수수료 몫은 풀 수수료 1.25%의 80% (= 거래량의 0.80%),
발행자 마이그레이션 수수료 0%, 졸업 LP 잠금. 따라서 `enable` 후 발행자의 온체인 수입은 정확히 아래 세 가지입니다.

| 출처 | 꺼내는 명령 |
|---|---|
| 본딩커브 크리에이터 거래 수수료 | `claim_curve_fees` |
| 커브 잉여금의 크리에이터 몫 | `claim_curve_surplus` |
| 잠긴 DAMM v2 LP 포지션 수수료 | `claim_amm_fees` |

## 출시 계획

1. **데브넷**: 실제 Meteora 데브넷 풀로 모든 명령을 끝까지 테스트합니다(`--features devnet`으로 빌드). SOL 코인의
   바이백 + 후원, 후원만, Token-2022 주식페어 대역 토큰.
2. **메인넷 시범 기간**: 수정 권한을 둔 채 배포, CREATORFUN 지갑만 켤 수 있음. 수정 권한 주소와 모든 수정 내역 공개.
3. **공개**: `PROBATION = false`와 수정 권한 제거를 같은 배포에서. 그 뒤로는 누구도 코드를 바꿀 수 없습니다.

## 빌드와 검증

```bash
cargo test --manifest-path programs/creatorfun-buyback/Cargo.toml        # 실행 규칙 단위 테스트
cargo build-sbf --manifest-path programs/creatorfun-buyback/Cargo.toml   # Solana 2.1.21, Anchor 0.31.1
sha256sum target/deploy/creatorfun_buyback.so
python3 scripts/mkidl.py programs/creatorfun-buyback/src/lib.rs idl.json  # 소스에서 클라이언트 IDL 생성
```
